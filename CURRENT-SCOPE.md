# Текущий объём: минимальный self-host

Прямое указание пользователя заменяет прежнее поручение исполнить весь roadmap.

Нужен минимальный работающий FRNESS, через который агент сможет написать следующие расширения сам:

1. Загрузка закреплённых метаописаний и plugin exports.
2. Один выбранный CLI backend (Codex или Claude): prompt, поток ответа, terminal result, continuation и interrupt.
3. Локальное сохранение состояния и явные точки подключения плагинов.
4. Одна команда запуска агента в рабочем репозитории и подключение написанного им пакета без правок host.
5. Проверка пути self-extension на небольшом плагине, созданном агентом через этот запуск.

Не реализовывать сейчас память, большой агентский цикл, UI, проекты, сессии поверх native CLI, форки и весь эксплуатационный roadmap. Уже опубликованные дополнительные пакеты остаются опциональными и не включаются в минимальную сборку.

Лимиты и статистика остаются отдельными плагинами. Требование hot reload сохраняется в архитектуре; не заявлять полноценную поддержку до её фактической проверки. Расширения получают собственные схемы, логику, namespace и слоты через метамодель.

Дальнейшие функции агент разрабатывает внутри FRNESS по конкретным задачам пользователя, с проверками и коммитами. Не начинать автоматически остальные атомы из plan.json.

Дополнение по прямому запросу пользователя: минимальная оболочка Electron с вопросом–ответом, выбором рабочего каталога/CLI, продолжением native сессии и interrupt входит в текущий объём. Это не разрешает исполнение остального UI roadmap.
